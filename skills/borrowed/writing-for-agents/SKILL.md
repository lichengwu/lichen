# 给 Agent 写文档

写给 agent 消费的任何文档的参考：一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、一份通过指针到达的文档。包装不同，写法相同：同样的杠杆让每一类都可预测，因为 agent 每次跑拿的是同一套*流程*，而不是产出同一个输出。

## 上下文指针

**上下文指针**是持有在 agent 上下文里的一个引用，它命名某份上下文之外的材料，并编码到达它的条件。skill 的 description 是一个；`AGENTS.md` 里点名一份文档的一行是同一个东西。指针的*措辞*（不是它的目标）决定 agent 何时到达材料、多可靠。一个必须有的目标躲在弱措辞指针后面，是一个方差 bug：先磨措辞，磨不动了再把材料内联。

一个指针做两件事：说明材料是什么，列出应该触发到达它的**分支**（分支是文档处理的一个 distinct 情形，所以不同的跑法在文档里走不同的路）。常驻指针的每个词每轮都在付费，所以它比正文更该被修剪：

- **领头词前置**：指针在领头词处干它的触发工作。
- **一个分支一个触发词。** 给同一个分支换说法的同义词，是一个分支写了两遍；合并，只留真正不同的分支。
- **删掉正文已经承载的身份信息。**

## 两种负载

你加的每份文档和指针，花的是两种预算之一：

- **上下文负载**是常驻材料在 agent 窗口上的成本：一行 `AGENTS.md`、一条 skill description、任何每轮坐在上下文里的东西，不管触不触发都在花 token 和注意力。
- **认知负载**是花在人身上的成本：有哪些文档、各自什么时候该伸手去拿。人是索引。不是要最小化的成本：它是人类主动权的价格；在人的判断重要的地方花它，在不重要的地方去掉它。

只通过指针到达的材料，逃掉了上下文负载，代价是指针自己那一行；完全没有指针的材料，全骑在认知负载上。

## 信息层级

一份文档由两种内容构成：**步骤**（agent 执行的有序动作）和**参考**（按需查阅的定义、规则、事实）。两者自由混合：全步骤（菜谱）、全参考（一份审查的规则、本技能）、或两者都有。核心决策是每一块落在**信息层级**的哪一级——这个梯子按 agent 多迫切需要材料排序：

1. **文件内步骤**是主层：agent 按顺序做什么。
2. **文件内参考**按需查阅。常常是一个合法的平级集合（一份审查的全部规则在同一级），这是合理安排，不是坏味道。
3. **披露参考**被推到单独文件，通过上下文指针到达，只在指针触发时加载。从同目录的兄弟文件一直到完全外部、任何文档都能指向的参考，都算。

往下推得太少，顶层膨胀；推得太多，把 agent 实际需要的材料藏了起来。这个张力就是全部决策。

**渐进披露**是沿着梯子往下走（移出主文件、藏到指针后面），让顶层保持可读。它主要不是 token 优化：它是层级的保护方式。分支是最干净的披露检验：每个分支都需要的内联，只有部分分支够得着的推到指针后面。有步骤的文档里，该披露的参考埋在文件里会把步骤埋掉，让 attending 它们变成抛硬币：这是一个方差杠杆，不只是可读性杠杆。

**同置（co-location）**是文件内的伴侣：层级决定一块材料坐*多深*，同置决定它坐*谁旁边*。把一个概念的定义、规则、注意事项放在同一个标题下，而不是散落各处，这样读一部分能把邻居带进来。检验：文档应该读起来像"写给 agent 的文档"。聚起来的材料读起来是这样；散架的材料不是。（和重复区分：重复是一个意思说两遍；散架是一个意思碎在多处。）

** sprawl（蔓生）**是这里的失败模式：一份文档就是太长，即使每行都活着都唯一。注意力在过量里变薄，每多一行就多一行要保鲜。解药是梯子：把参考披露到指针后面，按分支或时序拆分，让每条路只带它需要的。

## 步骤与完成标准

每个步骤结束在一个**完成标准**上，即告诉 agent 工作完成了的条件。两个属性让它成为杠杆：

- **清晰度**：agent 能分清完成和未完成吗？一个模糊的边界（"达成了理解"）招来**过早完成**：在工作真正完成前结束这一步，注意力滑向"显得完成"。前面还看得见的步骤（**完成后步骤**）提供拉力；标准的清晰度是阻力。按序防御：**先磨边界**（局部且便宜）；只有当它本质模糊*且*你观察到抢跑时，才拆序列把后面的步骤藏起来。藏只在跨越真实的上下文边界时有效（一次交接或一次 sub-agent 派发；内联调用会把后面的步骤留在上下文里，什么也清不掉）。
- **要求度**：它要求多少。"每个改动的模型都有交代"迫使彻底的活，而"产出一份变更清单"不会。要求度驱动**腿力**（agent 在工作内部做的挖掘，潜伏在措辞里而不是写成独立步骤），且它不受步骤约束："每条规则都适用"约束一坨平级参考，正如"每步都完成"约束一个序列——这就是一份全参考文档仍然背着 exhaustive 标杆的方式。

最强的标准既可检查又穷尽。

## 何时拆分

把一份文档拆成两份，花的是两种负载之一，所以只在切口挣得回来时拆：

- **按时序**：拆一段步骤，当完成后步骤诱惑 agent 抢跑当前步骤时。让它们不在视野里，驱动当前任务上更多的腿力。警惕反面：合并序列会把每步的后续暴露给它后面的事，招来过早完成。
- **按调用**（skill 专属）：调用型技能的拆分准则见 `.agents/invocation.md`。
